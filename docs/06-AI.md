## CEL BIZNESOWY — założenie zamawiającego

> „Artykuły mają być automatycznie przygotowywane przez rozwiązanie sztucznej inteligencji, czyli **edytor pisania tekstów zintegrowany z odpowiednimi modelami sztucznej inteligencji** — czy open source, czy dowolnym modelem zgodnym z OpenAI lub z Anthropic. **Podpinam klucz, daję prompta i dany model pisze dany artykuł**, może pomagać w pisaniu tych artykułów. Ma to być jedna z funkcji i opcji w edytorze tekstu. Jak są to wtyczki na przykład do WordPressa, które **piszą artykuły na zadany temat, mogą to robić określonej długości, są tam różne preferencje, ustawienia, tematyka, może wyszukiwać w internecie, może sprawdzać, poprawiać**."

Z tego wynika **6 wymagań funkcjonalnych**:

| Nr | Wymaganie | Odpowiednik w świecie WordPressa |
|---|---|---|
| W1 | Dowolny dostawca modelu — OpenAI, Anthropic, open source | wybór providera w AIOSEO / Bertha AI |
| W2 | Użytkownik podpina własny klucz API | pole „API Key" w ustawieniach wtyczki |
| W3 | Prompt → gotowy artykuł | „Write article about…" (AI Engine, GetGenie) |
| W4 | Ustawienia: długość, ton, tematyka, preferencje | panel parametrów (Content at Scale, Koala) |
| W5 | Wyszukiwanie w internecie | tryb „SERP research" (GetGenie, Koala Writer) |
| W6 | Sprawdzanie i poprawianie tekstu | „Proofread / Fact-check / Improve" |

Ten dokument opisuje, **jak to zrealizować technicznie** na stosie Hono + Cloudflare Workers, oraz co już jest gotowe.

## CZĘŚĆ A — CO JEST ZROBIONE

Warstwa AI liczy **1 328 LOC w 22 plikach**. To najbardziej dojrzały fragment backendu — ale w całości niepodłączony do interfejsu.

### A1. Klient dwóch dostawców — `src/ai/client.ts`

Funkcja `callStructuredModel()` obsługuje OpenAI i Anthropic z wymuszeniem JSON:

```typescript
const OPENAI_CHAT_URL = 'https://api.openai.com/v1/chat/completions'
const ANTHROPIC_MESSAGES_URL = 'https://api.anthropic.com/v1/messages'

interface StructuredRequest {
  bindings: AppBindings
  model: SupportedModel
  systemPrompt: string
  userPrompt: string
  jsonSchema: JsonSchema
  temperature?: number
  maxTokens?: number
}
```

Zwraca `{ provider, data, rawText, validated, validationErrors }`. Dla OpenAI używa `response_format: { type: 'json_object' }`, dla Anthropic wstrzykuje schemat do promptu systemowego. Waliduje odpowiedź przez `validateAgainstSchema()` z `src/ai/json-schema.ts`.

**To jest solidna podstawa pod wymaganie W1.**

### ⛔ B8. Brak strumieniowania odpowiedzi

Generowanie artykułu 800-słowego zajmuje 20–60 s. Bez strumieniowania (SSE) redaktor patrzy na zablokowany interfejs, co przy limitach czasu Workers grozi przerwaniem żądania.

Cloudflare Workers **obsługuje** strumieniowanie (`ReadableStream`, `TransformStream`), a OpenAI i Anthropic mają `stream: true` — ale kod nie korzysta z tej możliwości: `callStructuredModel()` czeka na całą odpowiedź (`await response.json()`).

## CZĘŚĆ C — ARCHITEKTURA DOCELOWA

### C1. Uniwersalny adapter dostawców — realizacja W1 + W2

Zamiast dwóch zaszytych URL-i — konfigurowalne profile dostawców przechowywane w bazie:

```typescript
// src/ai/providers/types.ts
export type ProviderProtocol = 'openai-compatible' | 'anthropic' | 'workers-ai'

export interface AiProviderProfile {
  id: string
  label: string                  // "OpenAI GPT-4o", "Ollama Llama 3.1 lokalnie"
  protocol: ProviderProtocol
  base_url: string               // np. "https://api.groq.com/openai/v1"
  model: string                  // np. "llama-3.3-70b-versatile"
  api_key_ref: string | null     // nazwa sekretu, NIGDY sama wartość
  max_context_tokens: number
  supports_streaming: boolean
  supports_json_mode: boolean
  supports_tools: boolean
  cost_per_1m_input: number      // USD, do liczenia kosztów
  cost_per_1m_output: number
  default_temperature: number
  is_default: boolean
  is_active: boolean
}
```

Ponieważ `openai-compatible` obsługuje przytłaczającą większość dostawców, **jeden adapter** wystarcza dla:

| Dostawca | `base_url` | Uwaga |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | dowolny model |
| Groq | `https://api.groq.com/openai/v1` | Llama, bardzo szybki |
| Together AI | `https://api.together.xyz/v1` | modele open source |
| Fireworks | `https://api.fireworks.ai/inference/v1` | j.w. |
| OpenRouter | `https://openrouter.ai/api/v1` | agregator ~200 modeli |
| Mistral | `https://api.mistral.ai/v1` | modele europejskie |
| DeepInfra | `https://api.deepinfra.com/v1/openai` | open source |
| **Ollama** | `http://<host>:11434/v1` | **model lokalny, zero kosztu** |
| **LM Studio** | `http://<host>:1234/v1` | j.w. |
| **vLLM** | `http://<host>:8000/v1` | własny hosting |
| Anthropic | `https://api.anthropic.com` | protokół `anthropic` |
| Cloudflare Workers AI | `env.AI.run()` | protokół `workers-ai`, w tej samej sieci |

**Uwaga architektoniczna dotycząca modeli lokalnych:** Cloudflare Workers nie może połączyć się z `localhost` użytkownika. Aby użyć Ollamy, instancja musi być dostępna publicznie (tunel Cloudflare, VPS z HTTPS) albo trzeba użyć **Cloudflare Workers AI** — modele open source (Llama 3.3, Mistral, Qwen) uruchamiane bezpośrednio w infrastrukturze Cloudflare przez binding `AI`, bez własnego klucza i bez ruchu wychodzącego. **Dla tego projektu Workers AI jest najsensowniejszą realizacją wymogu „open source".**

### C2. Przechowywanie kluczy — realizacja W2

Trzy poziomy, zależnie od potrzeby:

1. **Sekret Workers (zalecane dla klucza redakcyjnego)**
   ```bash
   npx wrangler pages secret put AI_OPENAI_KEY
   ```
   Profil trzyma tylko nazwę: `api_key_ref: "AI_OPENAI_KEY"`. Klucz nigdy nie w bazie.

2. **Klucz per użytkownik, szyfrowany w D1** — gdy każdy redaktor ma własny klucz i rozlicza się osobno:
   - Szyfrowanie AES-GCM przez Web Crypto API kluczem głównym z sekretu
   - Zapis wyłącznie szyfrogramu w `ai_user_keys`
   - W interfejsie widoczne tylko 4 ostatnie znaki (`sk-…f3a9`)
   - Nigdy nie zwracać klucza przez API, nawet administratorowi

3. **Bez klucza** — Workers AI (rozliczenie w ramach konta Cloudflare)

**Zasada bezwzględna:** klucz nigdy nie trafia do frontendu. Przeglądarka wywołuje wyłącznie `/api/v1/ai/*`, a Worker dokłada klucz po stronie serwera.

### C3. Schemat bazy dla AI

```sql
-- Profile dostawców
CREATE TABLE ai_providers (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  label TEXT NOT NULL,
  protocol TEXT NOT NULL CHECK (protocol IN ('openai-compatible','anthropic','workers-ai')),
  base_url TEXT NOT NULL,
  model TEXT NOT NULL,
  api_key_ref TEXT,
  max_context_tokens INTEGER NOT NULL DEFAULT 8192,
  supports_streaming INTEGER NOT NULL DEFAULT 1,
  supports_json_mode INTEGER NOT NULL DEFAULT 1,
  cost_per_1m_input REAL NOT NULL DEFAULT 0,
  cost_per_1m_output REAL NOT NULL DEFAULT 0,
  default_temperature REAL NOT NULL DEFAULT 0.7,
  is_default INTEGER NOT NULL DEFAULT 0,
  is_active INTEGER NOT NULL DEFAULT 1,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Klucze użytkowników (szyfrogramy)
CREATE TABLE ai_user_keys (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  provider_id INTEGER NOT NULL REFERENCES ai_providers(id) ON DELETE CASCADE,
  key_ciphertext TEXT NOT NULL,
  key_iv TEXT NOT NULL,
  key_hint TEXT NOT NULL,              -- 4 ostatnie znaki
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  last_used_at DATETIME,
  UNIQUE (user_id, provider_id)
);

-- Presety generowania (realizacja W4)
CREATE TABLE ai_presets (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,                  -- "Relacja z sesji rady gminy"
  description TEXT,
  category_slug TEXT,                  -- domyślna kategoria portalu
  target_length_words INTEGER DEFAULT 600,
  tone TEXT DEFAULT 'informacyjny'
    CHECK (tone IN ('informacyjny','reportazowy','urzedowy','publicystyczny','lekki')),
  audience TEXT DEFAULT 'mieszkaniec',
  language_level TEXT DEFAULT 'neutralny'
    CHECK (language_level IN ('potoczny','neutralny','formalny','uproszczony_b1')),
  structure_json TEXT,                 -- liczba śródtytułów, wymagane bloki
  system_prompt_extra TEXT,            -- wytyczne redakcyjne
  use_web_search INTEGER NOT NULL DEFAULT 0,
  use_rag INTEGER NOT NULL DEFAULT 1,
  require_sources INTEGER NOT NULL DEFAULT 1,
  forbid_clickbait INTEGER NOT NULL DEFAULT 1,
  provider_id INTEGER REFERENCES ai_providers(id) ON DELETE SET NULL,
  temperature REAL DEFAULT 0.7,
  is_active INTEGER NOT NULL DEFAULT 1,
  created_by INTEGER REFERENCES users(id) ON DELETE SET NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Rejestr wywołań: audyt, koszty, limity
CREATE TABLE ai_generations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  article_id INTEGER REFERENCES articles(id) ON DELETE SET NULL,
  user_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
  provider_id INTEGER REFERENCES ai_providers(id) ON DELETE SET NULL,
  preset_id INTEGER REFERENCES ai_presets(id) ON DELETE SET NULL,
  action TEXT NOT NULL,                -- 'write_article','improve','proofread','fact_check'…
  model TEXT NOT NULL,
  prompt_user TEXT,                    -- co wpisał redaktor
  prompt_system TEXT,
  web_search_used INTEGER DEFAULT 0,
  web_sources_json TEXT,               -- adresy użytych źródeł
  rag_docs_json TEXT,                  -- slugi artykułów z archiwum
  tokens_input INTEGER DEFAULT 0,
  tokens_output INTEGER DEFAULT 0,
  cost_usd REAL DEFAULT 0,
  duration_ms INTEGER DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'ok' CHECK (status IN ('ok','error','rejected','timeout')),
  error_message TEXT,
  output_accepted INTEGER,             -- czy redaktor przyjął wynik
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_ai_gen_user_date ON ai_generations(user_id, created_at);
CREATE INDEX idx_ai_gen_article ON ai_generations(article_id);

-- Limity budżetowe
CREATE TABLE ai_budgets (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  scope TEXT NOT NULL CHECK (scope IN ('global','role','user')),
  scope_ref TEXT,
  period TEXT NOT NULL CHECK (period IN ('day','month')),
  limit_usd REAL NOT NULL,
  limit_requests INTEGER,
  alert_at_percent INTEGER DEFAULT 80,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Oznaczenie artykułu (AI Act)
ALTER TABLE articles ADD COLUMN ai_assisted INTEGER NOT NULL DEFAULT 0;
ALTER TABLE articles ADD COLUMN ai_disclosure TEXT;
ALTER TABLE articles ADD COLUMN human_reviewed_by INTEGER REFERENCES users(id);
ALTER TABLE articles ADD COLUMN human_reviewed_at DATETIME;
```

## CZĘŚĆ F — ETYKA I WYMOGI PRAWNE

### F1. Zasady bezwzględne dla portalu informacyjnego

1. **Żaden artykuł nie publikuje się automatycznie.** AI przygotowuje szkic — decyzję o publikacji podejmuje człowiek. Portal informacyjny odpowiada za treść wobec czytelników i prawa prasowego.
2. **Każdy materiał z udziałem AI jest oznaczony** — wymóg przejrzystości (AI Act, art. 50).
3. **Fakty o osobach, kwotach, datach i decyzjach urzędowych wymagają potwierdzenia w źródle.** Model nie może być źródłem faktu o gminie.
4. **Zakaz generowania wypowiedzi przypisanych osobom.** Cytat może pochodzić wyłącznie z materiału źródłowego.
5. **Przegląd mediów: nagłówek + 1–2 zdania + link.** Nigdy przepisywanie cudzych materiałów przez AI — to naruszenie praw autorskich.
6. **Dane osobowe nie są przesyłane do modelu** bez podstawy prawnej — dotyczy szczególnie nekrologów i materiałów o zdarzeniach z udziałem osób.

### F2. Zgodność z AI Act (obowiązuje w UE)

| Wymóg | Realizacja |
|---|---|
| Oznaczenie treści generowanej | Etap AI11 — nota na artykule + schema.org |
| Nadzór człowieka | Etap AI11 — blokada publikacji bez akceptacji |
| Przejrzystość działania systemu | Strona polityki AI + `ai_generations` jako ślad |
| Dokumentacja techniczna | Ten dokument + rejestr wywołań |

### F3. RODO

- Klucze API użytkowników szyfrowane (AES-GCM), nigdy w postaci jawnej
- Prompty zapisywane w `ai_generations` — muszą podlegać żądaniu usunięcia danych
- Dane wysyłane do dostawcy AI: umowa powierzenia przetwarzania (OpenAI/Anthropic udostępniają DPA)
- Dostawcy poza UE: wymagane standardowe klauzule umowne; **alternatywa zgodna z UE: Mistral (Francja) lub Workers AI (możliwość wskazania regionu)**
- Anonimizacja w promptach: nie przesyłać adresów IP ani danych kontaktowych czytelników

### F4. Prawo prasowe

Portal informacyjny podlega prawu prasowemu — odpowiedzialność redaktora naczelnego za treść jest niezależna od tego, czy tekst napisał człowiek czy model. Dlatego akceptacja człowieka nie jest opcją konfiguracyjną, lecz wymogiem architektonicznym (twarda blokada w bazie, nie tylko w interfejsie).
